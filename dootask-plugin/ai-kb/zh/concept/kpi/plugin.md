# KPI 插件元信息

## 定义
KPI 绩效考核在 DooTask 中由社区插件提供，应用市场 app id 为 `kpi`，feature 短名 `kpi`。主程序不内置任何 KPI 代码，所有绩效逻辑都跑在独立 Docker 容器中，作为应用插件挂载到 DooTask 界面。版本号随应用市场发布的版本走，不固定。

## 关键属性
- **作者**：DooTask 官方
- **要求**：主程序版本 > 1.4.67（依赖新 API 能力）
- **运行形态**：单个 Docker 容器（镜像 `dootask/kpi:<version>`）
- **数据存储**：独立 SQLite 数据库，本地卷 `kpi_data` 挂载到 `/web/db`，不入主库
- **菜单注入**：安装后在「应用中心」注册「绩效考核」入口
- **重启策略**：`unless-stopped`，主机重启容器自动恢复

## 账号创建与角色分配（首次登录时）
KPI 账号在用户**首次进入插件（用 DooTask 令牌登录）时**自动建立并分配角色：

- 部门不存在则自动创建该部门
- DooTask 管理员 → KPI 内部 hr 角色
- 部门负责人 → KPI 内部 manager 角色
- 其余 → employee 角色

## 本地账号密码

- 在员工管理中添加员工时，必须填写初始登录密码。创建后将邮箱和初始密码告知员工，员工即可使用邮箱密码登录 KPI。上级可暂不配置，创建考核前再补齐。
- 已登录用户可在「设置 → 修改密码」输入当前密码、新密码及确认密码。修改成功后使用新密码进行邮箱登录。
- HR 可在员工列表点击「重置密码」，输入并确认新密码后告知员工。主管和普通员工不能调用密码重置接口。
- 以前由员工管理或平台登录创建、尚未设置本地密码的账号，请先联系 HR 重置密码，再使用邮箱密码登录；不能通过空密码登录。
- 密码至少 6 个字符，UTF-8 编码不超过 72 字节。后端沿用注册接口的 bcrypt 哈希保存方式，不返回明文密码，也不设置通用默认密码。
- 改密和重置只修改本地密码，现有 JWT 会话仍按原认证机制和有效期处理。

## 企业微信账号绑定

启用企业微信接入后，先登录 KPI，再在「设置 → 账号绑定」发起绑定。请在同一浏览器中完成授权，并允许 Cookie；授权链接有效期为 10 分钟，只能使用一次，不可转发给他人。链接失效或服务重启后，请回到设置页重新发起绑定。访问地址应与企业微信回调地址保持一致，避免使用 IP 发起后回到域名。

已绑定账号可在同一页面点击「解绑企业微信」，输入当前 KPI 账号密码确认。解绑后不能再用原企业微信登录本账号，但当前登录会话保留，也可以重新绑定其他身份。企业微信接入关闭时仍可解绑。未设置或忘记 KPI 密码时请联系管理员处理。

## 用户生命周期钩子
插件订阅了 DooTask 的用户事件，但只做在职状态同步，不在此建号：

- `user_onboard`：DooTask 重新启用某用户时，把 KPI 中**已存在**的对应账号标记为在职；KPI 中尚无此人时不处理（建号仍发生在首次登录）
- `user_offboard`：DooTask 删除 / 离职用户时，KPI 同步把对应账号标记为离职

## 信息同步规则
用户每次登录 KPI 时：

- 自动更新姓名、职位
- **角色保持不变**（不会因为 DooTask 角色变化而重新分配 KPI 角色）

## 不支持
- 不能离线安装到不联网的环境（需访问应用市场镜像源）
- 不能在主程序 < 1.4.67 的环境上安装
